# Hostile-input coverage (T404)

Which untrusted input surface is attacked by which test, and what is not yet covered. A cell says what the named tests
pin; "none" is a gap, not an oversight, and each gap has its reason. Go fuzz targets are listed in
`scripts/fuzz-targets.txt`, each with a committed seed corpus under `testdata/fuzz/` and a bounded run in CI
(`node scripts/fuzz.mjs smoke`); a crasher is fixed with a regression seed, never skipped. Written after reviewing PR #70.

| Surface | Attacked by | Not covered (reason) |
|---|---|---|
| Bot output over the API and CLI adapters (stdout lines, HTTP body) | `internal/adapter/hostile_test.go` (end to end through the Host: not JSON, unknown field, trailing text, two values, wrong types, bad base64, status and question floods, a line past the limit, a bot that keeps asking, a second final message, a 100 000-character error cut as valid UTF-8, a stalled bot ended at the host limit; every case checks that no goroutine outlives the Host); `wire_internal_test.go` (exact line limit, bounded read, which only unit tests pin); `FuzzReadMessage` | Duplicate keys inside a bot line: Go keeps the last, and a bot line has one field set that the adapter reads once; the first final message ends the task whatever follows |
| Task fields sent to a bot (context, caller, owner, content) | `hostile_test.go` `TestHostileTaskFieldsReachTheBotAsOneWellFormedLine` (quotes, newlines, NUL, ESC, invalid UTF-8, injected JSON, 64 KiB) | none |
| Local socket requests (`internal/localsock`) | `hostile_test.go`: `ExactKeys` table and `FuzzExactKeys` (crasher `{}0` found and fixed, kept as a seed); `TestHostileRequestsAreRefusedWithFixedCodes` (duplicate, escaped-duplicate and miscased keys, unknown field, array, empty, nesting 100 000 deep, bidi/control/invalid UTF-8 keys, NUL/bidi in the method, a 100 000-digit number, a 200-request flood; fixed codes only, nothing echoed, no goroutine left); `TestStalledPeersAreCutOffAndFreeTheirSlots` (silent and half-request peers fill every slot, are cut at the connection deadline, free the slots; the test uses connections whose deadline is fired by the test, so no clock or wait is involved); `localsock_test.go` (oversized request, connection limit, escaped maximum request, peer uid) | none |
| MCP server (`internal/mcp`) | `hostile_test.go`: duplicate/case-variant/unknown keys at the top level, in `tools/call` params and in tool arguments; duplicate in-flight id (fixed: refused); nesting past the decoder limit in arguments, params and id; NUL/bidi/invalid UTF-8 in names, ids and methods never echoed and every reply one valid UTF-8 line; a flood of 20 000 tiny lines; more than `MaxConcurrent` calls bounded in goroutines; a silent client freed by the context. `limits_test.go`, `TestAnOversizedLineEndsTheSession`, `TestServeLeavesNoGoroutinesBehind`, `FuzzServe` | none |
| Gateway frames to and from the daemon (`internal/frames`) | `hostile_test.go` (escaped and Kelvin-sign/long-s keys, NUL/newline/bidi/zero-width/non-ASCII digits/invalid UTF-8 in id, from, kind, reason, nonce, media type, raw, version; integer overflow and negative values in expiry and retry; 5 000-deep objects) plus `FuzzParseEvent`, `FuzzDecodePrekey`, `FuzzUnpackInner`, duplicate and mis-cased keys, nesting, exact limits | none |
| Envelope, padding, files, bindings, revocation, prekeys, replay table | `FuzzMessage`, `FuzzUnpad`, `FuzzUnpadShaped`, `FuzzDecryptFile`, `FuzzDecodeVerify` (binding, revocation), `FuzzIssue`, `FuzzVerify`, `FuzzAccept`, `FuzzReceive` and the exact-limit tests of each package | none |
| Gateway replies to the daemon (trust, connect token, enrollment, directory) | `FuzzGatewayReplies`, `FuzzReplies`, `TestOversizedGatewayRepliesAreRefused`, `TestTokenReplySizeLimitIsExact`, `TestDirectoryReplyLimitsAreExact` | none |
| Pipeline, caller (task payloads, replies, tables) | `TestMalformedTaskPayloadsNeverReachTheBot`, `TestMalformedRepliesAreNotAccepted`, `TestWaitingTableIsBounded`, `TestPendingTasksPerPeerAreBounded`, caller limit tests | none |
| Gateway HTTP and WebSocket (Device DO, connect, enroll, directory, login, session, A2A) | `gateway/test/*.test.ts`: malformed and oversized frames (1009 close at the limit), binary frames, duplicate hello, replayed challenge and cancel, control/bidi characters in names, unknown fields, rate limits and floods, fail-closed limiter | **Follow-up task: gateway TypeScript fuzz targets** with committed seed corpora and a bounded CI run (a fast-check or jsfuzz style harness for the WebSocket frame parser, the A2A JSON-RPC body and the enroll/directory/login request bodies). Reason: it needs new tooling and a CI job in the gateway, not a change to this PR. Memory and CPU ceilings do not apply to Workers (the platform bounds them) |
| Replays | gateway `a2a`, `connect`, `task` tests; `internal/replay`, `TestConcurrentDuplicateWinsOnce` | none |

The local socket stall test fires the connection deadline by hand (a fake connection whose read ends when the test says),
so it is instant and independent of the machine. The adapter stall test still uses a real 1 s host limit with a generous
wait (a task limit is a context timeout inside the Host and has no seam); a slow machine only takes longer.

T404 stays open in `tasks.md` until the gateway TypeScript fuzz follow-up is done; every Go surface above is covered.
